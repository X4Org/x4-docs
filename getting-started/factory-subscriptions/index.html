Use Your Subscriptions In Factory

Connect your Codex / ChatGPT or Claude Code subscription through Mastra Factory's built-in provider connections. X4 sign-in and provider sign-in are separate; you do not need an API key for the subscription connection.

Connect Your Account​

  1. Connect Tailscale and open Mastra Factory. Your personal Tailscale identity normally signs you into X4.
  2. Open Settings → Models, choose OpenAI or Anthropic, and start subscription sign-in with personal/user scope. Skip sign-in if connected.
  3. Complete your provider's flow, then return to Factory:
SubscriptionSign-in flow
Codex / ChatGPTOpen the authorization link, sign into your ChatGPT account, and enter the device code. Wait for Factory to confirm the connection.
Claude CodeOpen the authorization link, sign into your Claude account, and paste the authorization code into Factory when prompted.

Personal First, Shared Fallback​

The X4 Factory build defaults to your connected personal OpenAI or Anthropic model. If neither personal connection is available, or its expired token cannot be refreshed, it automatically selects shared access, including X4 Gateway. Board runs use the saved session owner's connection. Coding, subagents and memory follow this policy; existing conversation model selections are retained.

Rollout: this policy is implemented and tested locally on this branch. It has not yet been deployed to Factory.

Start a new conversation after connecting. Check the model picker: native OpenAI / Anthropic uses that provider's resolved connection; X4 Gateway uses shared access. You can explicitly select Gateway.

Check That It Works​

  1. While signed in, open provider status. Find your provider and check source: "oauth-user" and userCredential: "oauth". An additional orgKey: true means a shared credential also exists; it does not override the personal source in this view.

  2. Send this in your new conversation:

    Run pwd and git branch --show-current, then reply SUBSCRIPTION_TEST_OK. Do not change any files.

  3. Confirm the shell tool succeeds and the reply contains the marker.

A successful tool run confirms inference and tools work. Provider status shows stored configuration; it does not prove which credential served that request or provider-side billing.

If It Does Not Work​

  • Not logged in…: reconnect the provider at personal scope and retry.
  • oauth-org or stored-org: the status view is selecting a shared organization credential. Complete your personal subscription sign-in.
  • stored-user: your personal connection is an API key; use subscription sign-in.
  • x4-gateway/* model: shared access is selected. Check your personal connection, then start a new conversation or select a native model.

Fallback checks stored credentials and token refresh before selecting a default. A provider may still reject a request for quota, a revoked token or an outage; those errors are surfaced, without automatically replaying the run on Gateway. If the credential changes from a subscription token to an API key during a request, Factory stops that request before sending the key. Reconnect or select a shared model and retry.

Request-level credential-source logging is not yet available. Provider status can still show a stored personal connection whose refresh fails; check the selected model and run result too.

X4 test status and hosted-provider support

On November 9, 2026, an existing personal OpenAI connection passed a live conversation and shell-tool call. Our Anthropic connection returned Not logged in to Anthropic; successful inference remains unverified. Fresh sign-in, renewal, and billing attribution still need validation.

Factory provides both connectors natively. Provider support for hosted usage is a separate question: the pinned OpenAI connector differs from the documented hosted Sign in with ChatGPT integration. Anthropic restricts third-party subscription-token inference and documents hosting unmodified Claude Code separately.
