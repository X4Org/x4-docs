Documentation on Control

The docs are X4 Control's Docs service, next to Fleet, Gateway and Projects in Control's service picker, at https://control.x4app.dev/docs/. Pages carry Control's shared header and theme. Old /x4/ links redirect to the same page under /docs/. The K12 setup guide is under Operations → K12 Prevent setup and the authentication specification is under Reference → CoreLayer preview authentication. Access to Control requires Tailscale.

The repository also publishes public documentation to https://docs.x4app.dev/ and the legacy https://x4app.dev/x4/. Those Pages publications do not update the Control copy.

Publish a Control copy​

Build with X4_DOCS_TARGET=control. That sets the site address to https://control.x4app.dev/docs/ and adds Control's shared header above the docs navigation, and imports X4 Code's own user docs from the private X4Org/x4-code repository as the X4 Code section, so the machine that builds needs read access to it. The prebuild script generates the authentication page and K12 setup page from their reviewed Markdown sources and includes the standalone specification, registry and blank environment template as downloads.

Stage the complete static build on Control and run the publisher described in the downloadable publication runbook. The publisher script is included with this docs release. It publishes an immutable release under /srv/x4/documentation/releases/, updates /srv/x4/documentation/current, and attaches /srv/x4/fleet/dist/docs to that current release. It does not require a Control, Gateway or ingress restart. The publisher records rollback information.

Control serves static files before its application fallback, and answers a missing page under /docs/ with the docs' own 404 page. If dist/docs is missing altogether, a documentation URL returns HTTP 200 containing the Control app instead. Verify the page's content and assets, not just its status code.

Check the publication​

  • Open the K12 setup guide and authentication specification through their Control URLs; confirm the expected headings and configuration instructions.
  • Confirm the Control header shows Docs selected, and that the service picker opens Fleet, Projects and (for owners and admins) Gateway.
  • Check a stylesheet or script URL referenced by the page and the specification's Markdown/HTML/JSON downloads, K12 registry and blank dotenv template.
  • Confirm Control's frontend and protected API behavior, the Gateway, existing previews and broker health match their prepublication state.
  • Record the source commit, static build hash, release path, verification and rollback details. A docs publication does not provision K12 credentials or establish that real CoreLayer sign-in has passed.

Preserve the docs during Fleet updates​

Fleet UI builds may replace dist/. A Fleet deployment must preserve or recreate dist/docs using the publisher's attachment procedure and verify both documentation pages afterward. The release and current link live outside Fleet's build directory so rebuilding the UI does not remove the docs files.
